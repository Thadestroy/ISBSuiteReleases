Viewer Points

Custom channel currency with earn rules, a redeemable shop, and timed point drops on the overlay.

Leaving a currency, shop item, or point-drop editor with unsaved changes shows Save, Don't Save, or Cancel. Opening an editor and leaving without edits does not prompt.

At a glance

  • Balances live on a per-user counter.
  • Watching earn rules need Stats - Watch Time and the Twitch chatters scope.
  • Event earn rules (chat, follow, sub, bits, raid, channel points) award when the chatter has a Twitch user id.
  • Shop items run full Actions (wheel, sound, giveaway, automation, Run Alert, and more).
  • Community Goals can spend a bound currency 1:1 into a goal (contribute command on the goal).
  • Point Drop needs a Point Drop widget on the active layout.
  • Free: 1 currency, 5 shop items per currency, 1 point drop per currency. Full limits on Free and Pro.

Creating a currency

  1. Give it an internal name and display name.
  2. Choose or create a per-user counter to back the balances.
  3. Set the balance command (for example !points) and response template.
  4. (Optional) Add Earn Rules to award points automatically.
  5. Add shop items viewers can spend points on.
  • Also customize the not-enough-points message and redemption confirmation message.

Earn rules

On each currency editor, open Earn Rules and click + Add Earn Rule. Points always go to the viewer who earned them (the person who chatted, followed, raided, and so on), not to everyone in chat.

Watching (live presence)

Awards points on a timer while a viewer is in chat during a live stream:

  1. Set Rule Name and choose trigger Watching (live presence).
  2. Award every: interval (seconds, minutes, or hours).
  3. Points they earn: how many points per interval.
  4. Optional extras for current Tier 1, Tier 2, and Tier 3 subscribers live under Advanced Settings (added on top of the base amount). Prime counts as Tier 1. Set Points they earn to 0 if only subscribers should get points. Gifted subs count. Leave extras at 0 for everyone to earn the same. The same extras can be set on Subscription and Resubscription event rules.
  5. Save the currency.

Prerequisite: enable Stats - Watch Time and ensure Twitch is connected with the moderator:read:chatters scope (reconnect on Integrations if watch-time accrual is paused). Watching earn rules use the same once-per-minute live poll as watch time. If Watch Time is off, the app prompts you to enable it before saving an enabled Watching rule. Other earn triggers do not need Watch Time.

Event triggers

Same event family Automations already see, when the event carries a Twitch user id:

  • Chat Message - that viewer earns after sending the number of chat messages you set (for example 10 messages then 5 points). Commands like !points do not count.
  • Follow
  • Subscription and Resubscription
  • Subscription Gifter - points go to the gifter, once per gifted sub (a bomb of 5 gifts awards 5 times). Optional gift count with At least or Exactly; leave blank for every gift
  • Subscription Gift Receiver - points go to the person who received the gifted sub
  • Raid - points go to the raider. Optional raider count with At least or Exactly; leave blank for every raid
  • Bits - points go to the viewer who spent bits (chat cheer or Power-Up). Optional bit amount with At least or Exactly; leave blank for every spend
  • Channel Point Redemption - points go to the redeemer. Optional reward name; leave blank for every reward

Tiltify donations are not an earn trigger: they do not identify a Twitch viewer, so points cannot attach to a real account.

Viewer and admin commands

  • Balance: viewers type !points (or your custom command) to check balance.
  • Give: viewers give their own points to another chatter (for example !givepoints).
  • Gamble: viewers wager points on a configurable win-chance roll (for example !gamble 50, !gamble 50.2, !gamble 34.7%, or !gamble all). Decimals and percents round to a whole stake before the roll.
  • Admin give: broadcaster/mods award points from chat (for example !vpgive).
  • Each command supports aliases and optional Match anywhere in message under Advanced Settings.
  • Advanced Settings also cover permission, time cooldown (optional burst), and per-stream limits (same unified editor as other commands).
  • Community Goals can bind this currency so viewers spend it into a milestone. See Community Goals - Viewer Points contribute.

Shop items

  • Viewers spend points to trigger actions: load a wheel, play a sound, start a giveaway, send chat, increment a counter, run an automation, Run Alert, and more.
  • Per-item price and purchase confirmation message.
  • Advanced Settings: permission, cooldown (optional burst), per-stream limits, command aliases, and Match anywhere. Longer aliases pass the remainder as {input}.

Useful variables: {balance}, {currencyName}, {price}, {itemName}. Full list: Message variables.

Point drops

Timed events where a configurable image or GIF appears on the overlay; chatters type a claim command to take a share of the drop. Configure under the Point Drops sub-tab:

  • Drop interval: how often (in minutes) the drop can spawn.
  • Spawn chance: percentage probability at each interval check.
  • Display duration: how long the drop image stays visible.
  • Claim command: chat command viewers type to claim (aliases and Match anywhere supported).
  • Claim slots: randomized range (min/max) for how many successful claims can happen before the drop ends.
  • Points per claim: how many viewer points each successful claim awards (default 1).
  • Drop image/GIF: shown in the Point Drop widget on your overlay.
  • Optional claim sound with volume control.
  • Optional already-claimed chat message when a viewer tries to claim again on the same drop (one claim per viewer). Leave the field empty to stay silent.
  • Supports only-when-live mode to skip starting-soon screens.

Spawn, claim, already-claimed, and expiry messages can use {amount} for points per claim, {pool} / {claimsLeft} for claim slots, and {pointsPool} / {pointsLeft} for total/remaining points (slots x amount). Prefer {pointsLeft} when Points per claim is greater than 1 so chat does not look like a slot count. An active drop is frozen at spawn: claim amount, claim slots, claim command, and chat templates stay as they were when that drop appeared. Saving the Point Drop editor updates the stored config for the next spawn only. Related: Overlay Layout - Point Drop, Counters and Stats (Watch Time), Use cases.
