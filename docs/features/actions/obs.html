OBS Studio

Talk to OBS Studio on this PC when the rule fires. After setup under Integrations, the action card stays available even if OBS is closed. Disconnect hides the empty card until you Connect again. Scene and source names are saved as text.

At a glance

  • UI label: OBS Studio.
  • Set up OBS under Integrations and Connect (OBS Studio 28+ with the built-in WebSocket server). After setup, the action card stays available so you can set scene names even if OBS is closed that day. Disconnect on the Integrations card hides the empty action card until you Connect again, including after you close ISB Suite. Rules that already have an OBS action keep the card if you Disconnect or clear the password, with a notice that the action will be skipped. ISB Suite never starts OBS for you.
  • Rules you already saved keep their OBS rows. If OBS is closed when the rule fires, that action is skipped and the rest of the rule still runs.
  • Available on Free and Pro. A failed OBS request is logged and does not stop the rest of the rule.

How it works

When the parent rule fires, ISB Suite sends each enabled operation to the connected OBS WebSocket (switch the program scene, show or hide a source, mute or unmute an input, set volume, start or stop streaming, start or stop recording). You can stack several rows on one rule (for example switch scene and unhide a source).

If OBS is closed, not connected, the password is wrong, or a single row fails (missing scene, unknown source), that row is skipped and the rest of the rule still runs (sound, chat, alerts). Existing automations, Chat Bot commands, and other hosts keep the OBS rows you already saved and show that OBS needs to be reconnected. Show / hide looks up the current scene-item id from the scene name plus source name at fire time, so a source you moved between scenes still works if you keep both names correct.

With a delay Timer on the same rule, OBS waits until that countdown ends (same timing as Send Message and Spotify).

Setup

  1. In OBS: Tools â†’ WebSocket Server Settings. Enable the server (OBS Studio 28 or newer). Default host 127.0.0.1, port 4455.
  2. On Integrations, OBS Studio: Set Up OBS opens a window for host, port, password, and Auto Connect. Connect there. Use Reconfigure later to change those fields.
  3. On the rule, enable OBS Studio, pick an operation, and fill scene / source / input names. Combos list live names when connected; you can still type a name OBS does not have open right now.

Operations

  • Set program scene: scene name.
  • Show / hide source: scene name, source name, and Show or Hide.
  • Mute / unmute input: input name and Mute or Unmute.
  • Set input volume: input name and volume in dB.
  • Start stream / Stop stream.
  • Start recording / Stop recording.

Pitfalls

  • This is OBS Studio WebSocket v5 only. Streamlabs Desktop uses a different protocol - use the Streamlabs Desktop action.
  • OBS 27 with the old 4.x plugin is a setup error. Use OBS Studio 28 or newer.
  • Start stream will go live if OBS accepts it. The editor warns: use with care.
  • ISB Suite does not launch OBS. Open OBS and enable the WebSocket server first.
  • Keep host at 127.0.0.1 unless you know you need another machine. Binding OBS to every network interface exposes the socket on your LAN.
  • This action does not replace Window Capture of the ISB Suite overlay. Capture setup stays on Download - Capture.

Examples

  • Raid -> Set program scene to your raid layout, then unhide a "thanks for the raid" source.
  • Channel point redeem -> Show a source on the current scene for a few seconds (pair with a Timer and a second rule or Action Set to hide it again).
  • Mod-only Chat Bot command -> Mute Desktop Audio, or switch to a BRB scene.
  • Stream ending command -> Stop recording (prefer this over Start stream unless you mean to go live).
