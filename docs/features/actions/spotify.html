Spotify

Control the Spotify app already open on your PC. ISB Suite never plays Spotify audio itself. Connect under Integrations first (Spotify Premium required).

At a glance

  • UI label: Spotify.
  • Connect under Integrations (your own Developer app + Client ID, no secret). The Spotify action and Chat Bot !sr / !remove stay hidden until you Connect.
  • Keep the Spotify desktop or mobile app open and play something once so a device is active.
  • Viewers can also queue with built-in !sr and undo with !remove (see Chat commands).

How it works

When the parent rule fires, ISB Suite sends a Player command to the official Spotify app (pause, resume, skip, shuffle, repeat, queue, play now, or Pause Then Resume At End). A Spotify error (not connected, Free account, no active device) is logged and does not stop the rest of the rule (sound, chat, alerts still run).

Queue adds a track behind what is playing. Play now starts that track immediately. Both accept a song name, an open.spotify.com/track link, or a spotify:track: URI. Message variables such as {input} resolve the same way other action fields do.

Pause Then Resume At End pauses as soon as this rule starts (before Play Sound), then resumes when this rule's sound, TTS, alert overlay, and auto-spin wheel have finished. It does not wait for a Timer (the Timer delays the whole payload), a giveaway until a winner, or a chat game. Two overlapping rules keep Spotify paused until both have finished.

Setup

  1. On Integrations, finish Set Up Spotify and Connect with Spotify. Playback needs a Spotify Premium account.
  2. Open the Spotify app and play something once so a device is active.
  3. On the rule, enable Spotify, pick a command, and for Queue / Play now fill Song or Spotify link.

Commands

  • Pause / Resume / Skip next / Skip previous.
  • Shuffle: check Shuffle on, or leave it off to disable shuffle.
  • Repeat: Off, Track, or Context.
  • Queue / Play now: song search or a track link. Album and playlist links are not supported. Blank song field cannot save.
  • Pause Then Resume At End: pause immediately, resume when this rule's clip, TTS, alert, or auto-spin is done. Walk-on setup: First Message + Play Sound (bypass queue) + this command.

Pitfalls

  • Development Mode apps only work for Spotify accounts you add under User Management on the Developer Dashboard.
  • If Spotify is closed or idle, commands fail with a no-active-device message until you play something once.
  • Spotify Free accounts cannot be controlled (Premium required).
  • For viewer requests, prefer built-in !sr / !remove instead of a custom Chat Command that only runs this action (Chat Bot already has permission, cooldown, and a confirm template).
  • This command is not a general "run anything at the start / end of an automation" slot. It only waits for sound, TTS, alert, and auto-spin on this rule.

Examples

  • Channel point redeem -> Queue {input} so the redeem text is the song name.
  • Mod-only Chat Bot command -> Skip next when chat is tired of a song.
  • Raid hype -> Play now a known track URI.
  • Walk-on clip -> Pause Then Resume At End + Play Sound (bypass queue) so Spotify does not clash with the clip.
