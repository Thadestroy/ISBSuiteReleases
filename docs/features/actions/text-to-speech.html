Text-to-Speech

Speak an announcement when the rule fires. Read the Send Message text, a custom TTS template, or both. Built-in voices need no cloud API key.

At a glance

  • UI label: Text-to-Speech.
  • You must enable at least one read option or nothing is spoken.
  • Custom TTS text supports variables; spoken after Send Message text when both are on.
  • Use Test TTS before going live.
On this page
  1. How it works
  2. Setup

How it works

On fire, TTS speaks the selected sources through the chosen voice, volume, and audio channel. If both Send Message and custom TTS text are enabled, Send Message is spoken first, then the custom TTS line. The editor warns if TTS is on but neither read option is checked.

Setup

  1. Enable Text-to-Speech.
  2. Check Read Send Message Response via TTS and/or Read TTS Text via TTS.
  3. If using custom text, fill TTS Text (supports {input} and other variables).
  4. Pick voice, volume, and channel, then Test TTS.

Read options

  • Read Send Message Response via TTS: speaks whatever the Send Message template resolved to. Enable Send Message on the same rule (or accept that there is nothing to read).
  • Read TTS Text via TTS: speaks the dedicated TTS template - useful when chat should be short and speech should be longer (or the reverse).
  • Voice / Channel: same audio-bus idea as Play Sound.

Alerts can also speak on their own TTS settings; this action is for Automations / Chat Bot / shop / games Actions surfaces. See Alerts.

Examples

  • Raid -> Send Message for chat plus TTS text {user} is raiding! so the room hears it if chat scrolls.
  • Shop redeem -> TTS only (no chat) for a private-feeling on-stream callout.
