Community Goals

Stream-wide milestones fed by Twitch events, chat message patterns, Viewer Points spend, or manual pushes from automations.

Leaving Add/Edit Goal with unsaved changes shows Save, Don't Save, or Cancel. Opening a form and leaving without edits does not prompt. Form Cancel discards without asking.

At a glance

  • Accumulation modes (combine freely): Manual, Twitch Data, Chat Message, Viewer Points.
  • When the limit is hit: Carry Over, Zero Out, or Stop at limit (bar stays full until Reset).
  • Check command example: !bitsgoal replies with {goalProgress} like 15/100.
  • Viewer Points contribute: viewers spend a bound currency 1:1 into the goal (for example !goal 50). Stop-at-limit goals reject further spend once the bar is full.
  • Fire Automations or Custom Alerts on Community Goal Reached.
  • Do not double-count Blerp-style bits (use Chat Message mode or Chat Message Match push, not both).
  • Free: 3 community goals. Full limits on Free and Pro.

Accumulation modes

Set a limit and one or more accumulation modes (checkboxes; combine freely):

  • Twitch Data: pick one or more EventSub sources from the dropdown (Bits / Cheer, Power-Up, new sub, resub, gifted, follows, raids). New sub matches first-time New Subscription, not a resub. New, resub, follows, and raids always add +1; Bits, Power-Up, and gifted subs use Count method (raw amount or +1 per event).
  • Chat Message: watch a specific chatter and a pattern with <amount> (useful for extension bits that never fire as Twitch cheers).
  • Viewer Points: viewers spend a bound currency into this goal (1 point = 1 progress).
  • Manual: progress from Push Community Goal actions only.

Automations can also use Chat Message Match plus Push Community Goal with Use amount from trigger.

Reset behavior

Choose what happens when progress hits the limit:

  • Carry Over: overflow counts toward the next cycle. The bar can look empty right after an exact hit. Goal Reached still fires, and further progress continues.
  • Zero Out: the bar resets to 0 after each completion. Goal Reached fires, and further progress continues.
  • Stop at limit: the bar stays full. Goal Reached fires once. Twitch, chat, Push, and Viewer Points add nothing more until you Reset (or stream-start reset, if that is on). Decrementing below the limit reopens the bar.

Manual Reset zeros the bar and cycle count. If viewers have contributed Viewer Points, the confirm dialog says those points are not refunded. Use Refund VP to credit them and reset the bar. Reset-when-stream-starts also does not refund (no dialog).

Viewer Points contribute

Enable Viewer Points on the goal and pick an enabled, unlocked currency. Viewers spend that currency 1:1 onto the bar. A SQLite ledger remembers each account's spend so you can refund later.

  • Contribute command is optional. Leave it empty to keep Viewer Points on but disable chat contribute. Viewers type the command plus a whole number (for example !goal 50). Bare command with no amount is not a contribute.
  • The contribute name may match the Check command: !goal checks progress, !goal 50 spends 50. Longest match and leftover text still apply.
  • Advanced Settings: aliases, match anywhere, permission, cooldown (optional burst), and per-stream use limits (same as other chat commands). Optionally cap how many points can go into the goal this stream, and how many each viewer can put in this stream (0 = unlimited). A typed amount larger than the remaining room is reduced to that remainder; chat explains when a cap is already full. Amount caps reset on a new stream and when you Refund VP.
  • Success and not-enough templates use contribute tokens such as {amount}, {balance}, {currencyName}, and goal progress tokens. Full list: Message variables - Community Goals.
  • Contribute commands appear on the Chat Bot overview. They are not a Run Chat Bot or Automation nested target.
  • On a Stop at limit goal, further spend is rejected once the bar is full (chat: This goal is already complete.). If the typed amount is larger than the remaining gap, only that remainder is spent and the success template {amount} is the applied amount.

Refund Viewer Points (overview or editor) credits every ledgered account, clears this goal's ledger, and resets the bar and cycle count. Goal Reached automations are not undone. Reset progress also does not refund (the Reset confirm dialog says so when the ledger has points). Delete with a ledger offers Refund and delete; if refund fails, the goal is not deleted.

Related: Viewer Points.

Check commands

  • Optional Check Command per goal (for example !bitsgoal) so anyone in chat can ask for progress.
  • Customizable response template. Default {goalProgress} replies like 15/100.
  • Other tokens: {goalName}, {goalCurrent}, {goalLimit}.
  • Advanced Settings: aliases, match anywhere, permission, cooldown (optional burst), and per-stream limits (same as other chat commands).
  • Check commands also appear on the Chat Bot overview; Edit opens that goal's settings.

Extension / Blerp bits

Chat Message mode watches a specific chatter and a pattern with <amount> (for example used <amount> bits). A line like CoolViewer used 25 bits to play ... becomes +25. Prefer this or a Chat Message Match automation that pushes the same goal - do not use both, or progress doubles.

When a goal is reached

Trigger Automations or Custom Alerts on Community Goal Reached (optional filter by goal). Related: Use cases, Message variables.
