Duel

PvP stake fight: challenge another chatter for an amount on a per-user counter. They accept or decline; a 50/50 roll transfers the stake from loser to winner.

At a glance

  • Preset: Duel.
  • Commands: !duel <user> <amount>, !accept, !decline (configurable).
  • Both viewers must afford the stake at challenge time and again on accept.
  • Payout is a transfer of x (not a 2x pot).
  • Accept timeout is adjustable (default 60 seconds).
  • Related: Chat Games, variables.

How it works

  1. A viewer challenges with !duel @OtherUser 100 (command names are editable).
  2. ISB Suite checks that both the challenger and the opponent have at least that amount on the chosen per-user counter. If either is short, chat gets a not-enough style error and no challenge is opened.
  3. The opponent types !accept or !decline before the timeout. Decline and timeout move no points.
  4. On accept, balances are checked again. A fair 50/50 pick chooses the winner; the loser transfers x to the winner.

For a solo house bet with Win/Lose action phases, use Solo Gamble instead of Duel.

Setup

  1. Create a Duel from Chat Games (game type Duel).
  2. Pick the per-user counter used for stakes.
  3. Confirm challenge / accept / decline commands and Advanced Settings on each.
  4. Set the accept timeout (default 60 seconds) and optional min/max stake.
  5. Tune chat templates for challenge, result, decline, timeout, and opponent-not-enough.

Options

  • Counter: required per-user counter for the stake transfer.
  • Timeout: how long the opponent has to accept (default 60s).
  • Min/max stake: optional limits on the challenged amount.
  • Messages: challenge, result ({winner} / {loser} / {amount}), decline, timeout, opponent not enough.

Use cases

  • Points rivalry - Viewers stake currency against each other mid-stream.
  • Short fuse - 30-60s timeout so open challenges do not linger.
  • Soft economy - Min/max stake + command cooldowns keep transfers bounded.

Related: Solo Gamble, Heist (timed room).
