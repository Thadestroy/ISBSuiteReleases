Heist

Timed heist window: viewers bet a variable amount, each entrant rolls independently, and winners typically multiply their stake.

At a glance

  • Preset: Heist.
  • Timed join window; variable stake; independent win rolls per entrant.
  • Typical demo defaults: 50% win chance, 2x payout multiplier, each-entrant resolution.
  • Phases: Open, Join, Win, Lose, No Winners, When Session Ends, If No One Joins.
  • Variables: Chat Games tokens.

How it works

A start trigger opens the heist. Viewers join with the join command and stake an amount from the configured counter (variable stake). When the timer ends, each entrant is rolled independently against Win chance. Winners receive a payout from Payout multiplier (often 2x stake); losers forfeit. If people joined but nobody won, the No Winners phase can fire in addition to the end-of-session summary path.

Heist is the default "everyone rolls" timed game. Prefer Lottery when you want one shared pool winner instead.

Setup

  1. Create a Heist from Chat Games presets (or duplicate a working heist).
  2. Add a start trigger (command, channel points, and so on) that opens the session.
  3. Set join command, stake counter, variable stake mode, win chance, payout multiplier, and duration.
  4. Enable open / summary chat templates; add Countdown Warnings if you want mid-window reminders.
  5. Configure phase Actions (sound, alert, chat, counters) for Open / Join / Win / Lose / No Winners / When Session Ends as needed.
  6. Tune start Chat Command Advanced Settings (aliases, Match anywhere, permission) and the shared Start Triggers Cooldown & Limits card.

Options

  • Stake counter: which counter is debited and credited (often Stream Coins / Viewer Points currency).
  • Stake mode: Variable - viewers pass an amount after the join command.
  • Win chance %: independent roll chance per entrant when the session resolves.
  • Payout multiplier: winner payout relative to their stake (for example 2.0 = double).
  • Resolution scope: Each entrant (Heist-style) so every joiner is rolled.
  • Payout mode: Multiplier on stake for classic heist math.
  • Duration: join window length; Countdown Warnings use remaining-time offsets against this.
  • Execute Actions on resolve: when on, When Session Ends / resolve phase Actions run after outcomes are calculated.

Phases

  • Open - fire hype sound / alert when the window opens.
  • Join - optional confirm Actions when a stake is taken (keep chat noise low if you already send join-confirmed messages).
  • Win / Lose - per entrant after their roll; good for stings, Run Alert, or Counter Action on Wins.
  • No Winners - dedicated path when the session had entrants but zero winners; use {losersList} and {totalLost}.
  • When Session Ends - summary with {totalPool}, {totalPaidOut}, {winnersList}, {winnerCount}.
  • If No One Joins - soft fail when the window closes empty.

Messages and warnings

  • Opened template often includes {command} and {duration}.
  • Summary template often includes {winnerCount}, {totalPaidOut}, and {winnersList}.
  • Countdown Warnings: reminder text plus offsets (for example 60s and 10s left). Use {timeLeft}. Offsets at or beyond session length are skipped.
  • Full token table: Message variables - Chat Games.

Use cases

  • Friday night heist - Mod !heist opens a 2 minute window; Win phase plays a sting + Run Alert.
  • Quiet fail - No Winners phase sends a soft chat line with {totalLost} and skips hype sounds.
  • Channel points open - Redeem "Start Heist" as the start trigger; viewers still join with !heist <amount>.
  • Win board - Win phase Counter Action Change by +1 on per-user Wins, then Send Message with {user} and {count}.
